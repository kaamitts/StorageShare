# Sprint 1 — выполненная интеграция

На основе четырёх исходных ZIP. Макеты и основная архитектура авторов сохранены.

- Моки заменены на реальные fetch-запросы. `/api` проксируется Vite при разработке,
  Nginx в Compose. Для отдельного API есть VITE_API_BASE_URL.
- Единый клиент хранит access/refresh/user, обновляет токены при 401 и повторяет
  запрос один раз. Параллельные 401 используют один refresh-запрос.
- При logout тело запроса берёт актуальный refresh, включая его ротацию.
- При reload проверяется `/auth/me/`; при временной ошибке сети можно повторить.
- Защищены страницы точек и кабинет партнёра. Роль проверяется для кабинета;
  API списка точек доступен обоим типам авторизованных пользователей.
- Ошибки регистрации 400 выводятся под соответствующими полями; сеть/сервер
  не маскируются под неверный пароль. Имя и роль обязательны также в API.
- Цена везде за сумку в час. Районы — все 8, по стабильным кодам с переводами.
- Детали используют address, opens_at/closes_at, security_notes. Удалены
  вымышленные площадь и телефон точки. Адреса не переводятся автоматически.
- Фильтр хранится в URL и восстанавливается при возврате из деталей.
- Добавлены отмена устаревших запросов, ошибки загрузки и retry.
- Исправлен lint без отключения правил; label связаны с полями, карточки — ссылки.
- Compose поднимает PostgreSQL, backend и frontend, применяет миграции, seed,
  healthchecks. По умолчанию это локальная демонстрация, не production deployment.

Никакого API бронирований или кабинета управления точками в Sprint 1 не добавлялось.
Исходные материалы схемы и wireframes сохранены отдельно с пометкой об устаревании.
